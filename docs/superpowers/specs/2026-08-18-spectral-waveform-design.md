# Spectral Waveform — Design

**Date:** 2026-08-18  
**Status:** Approved in product discussion  
**Depends on:** `2026-07-25-shared-spectral-engine-design.md`

## Summary

Add two independent, opt-in Waveform display features to both Workspace and Dock:

- **Frequency Color** colors each channel envelope with a REAPER-inspired spectral-peaks
  treatment: dominant frequency selects hue and spectral tonality controls saturation.
- **Centroid** overlays a one-pixel spectral-centroid trace on a logarithmic frequency axis.

The classic Waveform remains the default. Both features share one Rust analysis path and one
retained visual-history row per channel. Workspace and Dock controls are independent display
settings, but enabling either view activates the same backend analysis; simultaneous views never
repeat FFT work.

## Product decisions

### Controls

Workspace Waveform and Dock Waveform expose the same settings:

```text
Frequency Color                         [toggle]
  Low / Mid Split                  [200] Hz
  Mid / High Split                [2000] Hz
Centroid                                [toggle]
```

- Both toggles default to Off and are independent.
- Split inputs are integer number fields, not sliders.
- Split fields appear only while Frequency Color is On.
- Valid values are within the active analysis range and must satisfy `lowMid < midHigh`.
- Empty, non-numeric, non-finite, or invalid-order drafts do not commit; the field restores the
  last normalized value.
- Settings contain no frequency-color legend.
- There are no row-level reset buttons. The existing reset icon in the Panel Settings title resets
  every setting for that one panel instance.
- Reset restores both toggles to Off and the splits to 200 Hz / 2,000 Hz.
- Workspace and Dock instances persist independently and participate in their existing preset
  systems.

Suggested persisted Workspace keys:

```text
waveformFrequencyColor
waveformLowMidSplitHz
waveformMidHighSplitHz
waveformCentroid
```

Dock controls use the equivalent module-local fields. Normalization is authoritative on every
load, update, preset apply, and reset path.

### Frequency-color semantics

Frequency Color is not a three-band energy stack and does not reuse the Spectrogram colormap.

For every channel and analysis row:

1. dominant frequency chooses a continuous hue;
2. the two user splits anchor the Low, Mid, and High regions of that mapping;
3. interpolation around the anchors is continuous in log-frequency space;
4. tonality controls how far the result moves from Neutral toward the frequency hue;
5. amplitude continues to control only the Waveform envelope geometry.

The default visual direction is:

```text
Low (warm orange/red) -> Mid (magenta/purple) -> High (blue/indigo)
```

This is REAPER-inspired behavior, not a copy of REAPER UI, presets, or exact color values.

Tonal signals receive saturated colors. Broadband/noisy signals approach Neutral. Silence and
invalid analysis use Neutral and never emit a random hue.

### Color tokens

Add Waveform-specific semantic tokens:

```text
--ui-waveform-frequency-low
--ui-waveform-frequency-mid
--ui-waveform-frequency-high
--ui-waveform-frequency-neutral
--ui-waveform-centroid
```

They are generated by the existing theme-token pipeline. Low/Mid/High use a stable
REAPER-inspired palette with light/dark contrast adjustment. Neutral is derived from neutral
foreground/surface semantics, not `--ui-waveform-trace`: the classic trace follows the theme
accent and is orange in the default theme, which would collide with Low. Centroid uses a
high-contrast neutral token and does not borrow selection, warning, snapshot, or Spectrum colors.

Frequency Color Off continues to use the existing `--ui-waveform-trace` and
`--ui-waveform-trace-snap` behavior unchanged.

### Centroid presentation

- One trace is drawn per channel lane.
- The trace is one screen pixel, solid, and has no glow.
- Its vertical coordinate is logarithmic from the active analysis minimum at the bottom to maximum
  at the top.
- The Waveform keeps its existing centered amplitude axis; the centroid trace is an explicitly
  optional overlay with a separate vertical meaning.
- No permanent frequency axis or legend is added.
- Existing Workspace hover may show the nearest centroid value in Hz when available. Dock remains
  compact and does not gain a new hover HUD in this feature.

## Analysis contract

### Activation

The frontend derives one boolean spectral-waveform analysis need:

```text
spectralWaveform = any visible Workspace or active Dock Waveform instance has
                   Frequency Color On or Centroid On
```

The backend wire request contains this required boolean. Split values are display-only and never
enter the request identity. Changing a split must not reset DSP, create a history gap, or send a
different FFT request.

When the boolean is false, no spectral-waveform consumer is planned and no additional channel FFT
work is performed. Enabling after capture or file analysis begins has the same warm-up/no-backfill
contract as other requested spectral consumers.

### Shared transforms

The implementation extends the existing Shared Spectral Engine. It must not add FFT, allocation,
locking, or syscalls to the audio callback. Physical-channel transforms are planned once and shared
with Spectrum or Stereo Map requests that already need the same channel and resolution.

Frequency Color and Centroid consume the same channel analysis. Turning both on costs no more DSP
than turning either one on. Workspace and Dock instances never create duplicate consumers.

The initial implementation analyzes every channel displayed by Waveform. Performance tests must
cover 2-, 8-, and 16-channel inputs and record transform counts. If the existing engine's
all-resolution stream allocation is materially too expensive for the high-channel case, the engine
must gain a resolution-need mask rather than silently sharing one channel's color across lanes.

### Per-row metrics

The retained output is deliberately compact:

```text
dominantFrequencyHz[channel]
spectralCentroidHz[channel]
tonality[channel]
```

- Frequencies are finite Hz values in the analysis range; zero means unavailable/silent.
- Tonality is finite and clamped to `[0, 1]`.
- Arrays are either all empty while inactive/unavailable or all equal to channel count.
- No color, split-derived category, CSS value, `NaN`, or `Infinity` crosses IPC.

Analysis covers 20 Hz through `min(20 kHz, Nyquist)`. The consumer derives a neutral power spectrum
on the existing log grid before display Tilt, display smoothing, peak hold, or color mapping:

- dominant frequency is the maximum finite spectral-density point, with local interpolation where
  the neighboring points permit it;
- centroid is `sum(f * P * bandwidth) / sum(P * bandwidth)`;
- tonality is a normalized spectral-concentration measure on the log grid: a narrow tonal peak
  approaches 1 and a broadly distributed spectrum approaches 0;
- a fixed low-level gate maps silence and numerically unreliable rows to zero/zero/zero.

The exact concentration constants and gate are DSP implementation constants, covered by reference
fixtures rather than user controls.

## IPC and history

The metrics ride on `VisualHistEntry`, whose live semantic cadence is 40 ms. File mode retains its
existing coarser checkpoint behavior. `FrameIntake` stores them in the existing visual Waveform
history alongside visual min/max and timestamps.

This placement provides:

- timestamp alignment with Spectrum/Spectrogram history;
- one shared retained source for Workspace, Dock, live, file, scrub, and snapshot;
- immediate recoloring of retained history after split edits, because Hz is stored rather than a
  precomputed Low/Mid/High category;
- constant payload size per channel instead of retaining a full spectrum row.

Changing splits only re-runs frontend color mapping. It does not clear or rewrite history.

## Rendering

Both Waveform renderers consume the same pure color-mapping and timestamp-alignment helpers.

For every device-pixel column:

1. existing Waveform math supplies the channel min/max envelope;
2. the nearest valid spectral row is found by timestamp within a bounded tolerance;
3. dominant Hz maps through Low/Mid/High anchors in log space;
4. the frequency hue mixes with Neutral according to tonality;
5. the column is painted only inside the existing envelope;
6. Centroid, if enabled and valid, is drawn above the envelope fill.

Adjacent colored bodies overlap by half a backing-store pixel at each horizontal edge. This keeps
sub-pixel envelope motion from exposing anti-aliased seams against the canvas background; the
waveform outline retains its original, non-overlapped coordinates.

If a column has no aligned spectral row, Frequency Color uses Neutral and Centroid has a gap. It
must not stretch stale analysis across seeks, resets, startup warm-up, or dropped-history gaps.

Classic mode keeps the current polygon path renderer and appearance. Spectral mode may use bounded
per-column painting because canvas width is already capped to one backing pixel per CSS pixel.
Long Dock windows retain their existing aggregation-stride optimization.

## Workspace and Dock integration

### Workspace

- Add normalized defaults and persistence to `DEFAULT_PANEL_CONTROLS`.
- Add Waveform rows to the existing `PanelSettingsContent` and title-level reset comparison.
- Feed the retained spectral rows into `WaveformPanel` without bypassing `AudioDataContext`.

### Dock

Dock already has per-panel settings and title-level reset infrastructure, but Waveform currently
registers `settingsFamily: null` and has no control schema. This feature:

- changes its family to `waveform`;
- adds defaults/normalization to `dockModuleControls.js`;
- adds the same setting rows to `DockModuleSettings`;
- keeps controls independently persisted per Dock panel id;
- reuses the existing `reset-module-controls` action;
- passes the same retained spectral history into `DockWaveform`.

## Accessibility and help

- Color is diagnostic assistance, not the only representation: the amplitude envelope is unchanged
  and Centroid can be enabled independently.
- Settings labels name the split semantics even though no legend is shown.
- Chart help explains dominant-frequency hue, tonality saturation, Neutral, and the fact that
  dominant frequency and centroid are not pitch detection.
- Numeric inputs have explicit accessible labels and Hz units.

## Testing

### Rust

- tone fixtures across Low/Mid/High and both split defaults;
- sine, multi-tone, deterministic noise, silence, impulse, and low-level gate fixtures;
- dominant/centroid bounds, finite output, tonality ordering, and per-channel independence;
- request activation, warm-up, Clear, sample-rate change, file timing, and removal;
- shared-transform counts with concurrent Spectrum/Stereo Map;
- 2/8/16-channel performance and allocation checks.

### Frontend

- control normalization, invalid draft behavior, persistence, presets, and title-level reset;
- Workspace and Dock settings parity with independent values;
- activation deduplication across multiple Workspace/Dock instances;
- log-frequency hue mapping, tonality-to-Neutral mixing, timestamp gap handling;
- classic renderer compatibility;
- Frequency Color, Centroid, and combined rendering in Workspace and Dock;
- snapshot/scrub/file history behavior and split edits without history reset.

### Repository and desktop

- Run focused Vitest and Rust suites throughout implementation.
- Run `npm run check` before handoff.
- Because `src-tauri/src/dsp` and `engine` change, run `npm run smoke:capture` on the real Windows
  capture rig before release.
- Run `npm run soak:capture` afterward (four hours by default); treat drift as a lead, not a verdict.

## Acceptance criteria

- Workspace and Dock expose matching Frequency Color, split, and Centroid controls.
- Their title reset restores all Waveform settings for only that panel instance.
- Classic Waveform is pixel-compatible when both toggles are Off.
- Frequency Color uses a fully opaque dominant-frequency fill from the zero line to both envelope
  extrema across the complete waveform body, including buckets whose samples fall on one side of
  zero.
  Tonality applies a perceptual chroma lift, with broadband or invalid data converging to a
  distinct Neutral.
- Centroid is independently usable and per-channel.
- Split edits recolor retained history immediately without backend request churn.
- Workspace and Dock share transforms and retained metrics; no duplicate FFT is introduced.
- Live, file, scrub, and snapshot paths use timestamp-correct finite data.
- Spectral rows interpolate against retained main-history timestamps instead of re-anchoring the
  complete color layer to each jittery newest live timestamp.
- No callback-thread realtime-safety regression is introduced.
- Automated checks pass and real capture smoke/soak follow-up is recorded.

## Performance baseline

The Criterion benchmark uses 0.512 seconds of 48 kHz audio per iteration, delivered in the
production 480-frame chunk size. Waveform-only analysis performs one 4096-point transform per
active physical channel and does not schedule the large or small spectral transforms.

| Channels | Transforms per update | Median time | Realtime throughput |
| -------: | --------------------: | ----------: | ------------------: |
|        2 |                     2 |   1.3024 ms |             393.12x |
|        8 |                     8 |   5.8893 ms |             86.937x |
|       16 |                    16 |   14.086 ms |             36.348x |

Measured on the development Windows machine with the `spectral_fft_count` Criterion benchmark.
